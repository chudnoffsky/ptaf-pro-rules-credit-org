# Правила PTAF Pro для веб-инфраструктуры кредитной организации

## О чем этот файл

Здесь собраны 24 правила и настройки межсетевого экрана уровня веб-приложений PTAF Pro 4.2.2, разработанные и проверенные на лабораторном стенде в рамках выпускной квалификационной работы. Из них 15 адаптационных (расширение или донастройка существующих механизмов PTAF Pro под профиль угроз банковского веб-приложения) и 9 авторских (закрывают пробелы, которых в Default Template нет совсем).

Под каждым правилом приведены: краткое описание сути, реализация (код или настройка через интерфейс) и UUID событий безопасности, которыми правило подтверждено на стенде. Полная таблица соответствия сценариев испытаний, правил и UUID лежит в `traceability/traceability.md`. Примеры переноса нескольких правил на ModSecurity, для иллюстрации vendor-independent подхода, в `portability/modsecurity-examples.md`.

> **Важно об адаптации.** Все маршруты (`/vulnbank/online/api.php`, `/vulnbank/online/login.php`) и имена полей (`amount`, `username`, `sms_code`) указаны применительно к лабораторному стенду Vulnbank. При развертывании в инфраструктуре конкретной кредитной организации эти значения необходимо заменить на фактические маршруты и имена параметров целевого приложения. Детектирующая логика (регулярные выражения, условия агрегации) от приложения не зависит и переносится без изменений.

**Стенд:** TRY PTAF (официальная платформа тест-драйва Positive Technologies), уязвимое банковское приложение Vulnbank, режим PTAF Agent (nginx 1.24.0 + ptafd 4.3.0).

## Адаптационные правила

Адаптационные правила настраивают и расширяют существующие механизмы PTAF Pro. Сами по себе они не покрывают атаки с нуля, но без них базовая конфигурация работает либо слишком грубо, либо вообще не подходит под банковскую нагрузку.

### WAF-01: Rate limit на маршрут

Простое ограничение по частоте запросов. Если с одного IP идет больше 20 запросов в секунду на любой URL, событие фиксируется и запрос блокируется с HTTP 403. Само по себе правило критичности не несет (низкая); его смысл — дать вход агрегации WAF-02, которая переводит адрес в blacklist.

Порог 20 запросов/сек подобран для лабораторного стенда и требует пересмотра под реальную нагрузку банковского приложения.

**Настройка через интерфейс PTAF Pro:**
```
Раздел:      Набор пользовательских правил -> Создать правило
Тип правила: Ограничение частоты запросов (Rate limit)
Маршрут:     /*
Порог:       20 запросов/сек с одного IP-адреса
Действие:    Block (HTTP 403)
Критичность: Низкая
```

Верифицировано: SCN-03 (детект) `25b555d4-e08e-40f7-866d-c131e1e3232b`, SCN-05 (блокировка) `5c0fab55-ed6e-4bed-a0c6-97f03bd3d49c`.

### WAF-02: Агрегация и blacklist

Связка с WAF-01: при накоплении 1000 срабатываний WAF-01 за 10 секунд адрес кладется в blacklist на 10 минут. Порог выбран нарочно низким для лабораторного стенда — на проде значение надо пересмотреть. UUID агрегационных событий в PTAF Pro начинаются с `00000006-`.

**Настройка через интерфейс PTAF Pro:**
```
Раздел:               Набор пользовательских правил -> Создать правило
Тип правила:          Агрегация
Правило-источник:     WAF-01
Порог агрегации:      >= 1000 срабатываний за 10 секунд с одного IP
Действие:             Close connection
Добавить в blacklist: да, TTL 10 минут
Критичность:          Средняя
```

Верифицировано: SCN-04 `00000006-9b6a-0b2d-f000-0000abbaa667`.

### WAF-03: User-Agent сканера

Логирование запросов с User-Agent, совпадающим с известными инструментами: `sqlmap`, `gobuster`, `nikto`, `curl`. Действие — `Log to db`, а не блокировка, поскольку эти UA встречаются и в легитимном трафике. На стенде внутренний мониторинговый агент использовал `curl/8.5.0` и попал под правило (SCN-23) — устранено добавлением IP мониторингового сервера в глобальный список исключений PTAF Pro.

```
if REQUEST_HEADERS.select("user-agent").extract(values).any()
   matches ~"(sqlmap|gobuster|nikto|curl)"
then Log to db
```

Критичность: Низкая.

Верифицировано: SCN-02 `38ee1a10-59b6-4ea0-81ab-a91570ad3ba1`.
Ложное срабатывание: SCN-23 `d204f6ca-fb43-4c5a-a3bf-d52f6d19ec4b` (устранено).

### WAF-04: SQL injection в GET/POST-параметрах

Расширение базового сигнатурного модуля `sqli_detector.so`: дополнительные паттерны `OR 1=1`, `UNION SELECT`, `extractvalue` в обычных параметрах формы и query-строки. JSON-тело это правило не покрывает — для него сделано отдельное правило WAF-05.

```
if REQUEST_QUERY matches ~"(OR 1=1|UNION SELECT|extractvalue)"
   OR REQUEST_POST matches ~"(OR 1=1|UNION SELECT|extractvalue)"
then Block
```

Действие: Block (HTTP 403). Критичность: Высокая.
Привязка: CWE-89, CVE-2022-21587 (CVSS v3.1 9.8).

> **Известное ложное срабатывание.** Поле `password` с одинарной кавычкой (например, `P@ss'word1`) может вызвать срабатывание: кавычка в пароле без контекста поля неотличима от начала SQL-инъекции. Решение — настройка исключения для поля `password` через механизм «пропуск части HTTP-запроса» в параметрах правила PTAF Pro.

Верифицировано: SCN-01 `ce1f6aa7-1bc8-4e75-8685-a88f82233b96`, SCN-08 `75093cfe-7377-4bdd-83d4-87613a37af70`, SCN-09 (блокировка) `cb9bd7be-d06e-4397-a743-b199176f97c8`.
Ложное срабатывание: SCN-22 `b6406832-9f07-46aa-a73d-aa7e59a3f81c` (устранено).

### WAF-06: XXE через внешние сущности XML

Срабатывает при наличии в теле XML-запроса одновременно `DOCTYPE`, `ENTITY` и `SYSTEM` — характерный признак атаки на XML-парсер с подгрузкой внешних сущностей. На стенде проверялось цепочкой: XXE -> SSRF -> чтение `/etc/passwd`.

```
if REQUEST_BODY matches ~"DOCTYPE"
   AND REQUEST_BODY matches ~"ENTITY"
   AND REQUEST_BODY matches ~"SYSTEM"
then Block
```

Действие: Block. Критичность: Высокая.
Привязка: CVE-2016-3718 (CVSS v3.1 8.6).

Верифицировано: SCN-06а `7103ed0b-a748-440a-b65a-eb72f1e7403d`, SCN-06б `b3b7eb2e-1309-4d44-8a65-7e43c60b36ae`, SCN-06в `9a0b8302-1e53-4495-935a-7ce038262d49`, SCN-07а (блокировка) `c2e7b23a-1fa4-45d9-b8b7-7af55f7207d8`.

### WAF-07: SSRF через XML

Дополняет WAF-06: ловит обращения к локальным ресурсам из XML-запросов. Покрывает `file://` (доступ к файловой системе) и адреса диапазона `169.254.0.0/16` (метаданные облачных провайдеров: AWS, GCP, Yandex Cloud).

```
if REQUEST_BODY matches ~"file://"
   OR REQUEST_BODY matches ~"http://169[.]254[.]"
then Block
```

Действие: Block. Критичность: Высокая.
Привязка: CVE-2016-3718 (CVSS v3.1 8.6).

Верифицировано: SCN-07б `48337d9c-caf4-4514-aa43-eafd82e1a4ce`.

### WAF-08: Детектирование попыток аутентификации

Инфраструктурное правило: логирует все попытки входа — как неудачные (коды 401/403), так и успешные (200 + `Set-Cookie`) — для агрегации в WAF-09 и аудита в WAF-10.

**Настройка через интерфейс PTAF Pro:**
```
Раздел:          Параметры аутентификации
Тип:             На основе форм
Метод:           POST
URL:             /vulnbank/online/login.php
Коды успеха:     200
Коды неуспеха:   401, 403
Cookie:          PHPSESSID
Действие:        Log to db
Критичность:     Информационная
```

> **Адаптация.** Маршрут `/vulnbank/online/login.php` заменить на фактический эндпоинт логина целевого приложения.

Верифицировано: SCN-11 (успех) `0ef9703e-0c9c-4ae5-a049-f479acf1510e`, SCN-12 (неуспех) `e9881a09-df65-49cf-a9fe-736a52c4307c`.

### WAF-09: Brute-force с агрегацией

Агрегатор поверх WAF-08. При 10 и более неудачных попытках входа с одного IP за 30 секунд адрес блокируется и добавляется в blacklist на 10 минут. UUID агрегационных событий начинаются с `00000006-`.

**Настройка через интерфейс PTAF Pro:**
```
Раздел:               Набор пользовательских правил -> Создать правило
Тип правила:          Агрегация
Правило-источник:     WAF-08
Порог агрегации:      >= 10 срабатываний за 30 секунд с одного IP
Действие:             Block
Добавить в blacklist: да, TTL 10 минут
Критичность:          Высокая
```

Верифицировано: SCN-13 `00000006-9bfb-08d9-f000-0000abbaa667`.

### WAF-10: Логирование успешной аутентификации

Зеркало WAF-08 для успешных входов: отдельный поток событий для аудита и SIEM-корреляций при расследовании компрометаций учетных записей.

**Настройка через интерфейс PTAF Pro:**
```
Раздел:          Параметры аутентификации
Тип:             На основе форм
Метод:           POST
URL:             /vulnbank/online/login.php
Коды успеха:     200
Cookie:          PHPSESSID
Действие:        Log to db
Критичность:     Информационная
```

На стенде покрывается SCN-11, UUID `0ef9703e-0c9c-4ae5-a049-f479acf1510e`.

### WAF-11: RCE через ImageMagick (CVE-2016-3714, CISA KEV)

ImageMagick исполнял shell-команды через имя файла при разборе SVG/MVG. CVE-2016-3714 включен в каталог CISA KEV с 28.03.2022 и продолжает эксплуатироваться в необновленных production-системах.

```
if REQUEST_BODY matches ~"[.](svg|mvg)"
   AND REQUEST_BODY matches ~"SYSTEM"
then Block
```

Действие: Block. Критичность: Высокая.
Привязка: CVE-2016-3714 (CVSS v3.1 8.4), CISA KEV с 28.03.2022.

Верифицировано: SCN-14 `14ad8f69-0704-4b27-b33d-611ad2483ad6`, SCN-15 (блокировка) `2beb0893-73dc-472d-a24c-456554bf13dd`.

### WAF-12: Webshell в HTTP-ответе (встроенный модуль)

Это не разработанное правило, а встроенный модуль PTAF Pro `webshell_detector.so`, активный в Default Template по умолчанию. Документируется для полноты: в наборе из 24 правил он учитывается как активная часть архитектуры защиты.

```
Реализация:  встроенный модуль webshell_detector.so (активен по умолчанию)
Условие:     паттерны eval(), system(), exec() в теле HTTP-ответа
Действие:    Block
Критичность: Высокая
```

Верифицировано: SCN-16 `d1cb0c36-825f-4a10-8715-cc71be6d27b9`.

### WAF-13: Обращение к загруженному webshell

Правило написано, но верифицировать на стенде не получилось: воспроизвести сценарий «загрузка webshell -> обращение к `/uploads/*.php`» в условиях лабораторного Vulnbank не вышло из-за конфигурации файловой системы. Включается в продуктивную среду после верификации на реальном стенде.

```
if REQUEST_METHOD matches ~"(GET|POST)"
   AND REQUEST_URI matches ~"^/uploads/[^/]+[.](php|phtml)$"
then Block
```

Действие: Block. Критичность: Высокая.

### WAF-16: XML bomb (DoS)

DoS через рекурсивные XML-сущности («billion laughs»). Парсер разворачивает вложенные сущности экспоненциально и по итогу исчерпывает ресурсы сервера.

**Настройка через интерфейс PTAF Pro:**
```
Раздел:    Защита от DoS -> Ограничения XML
Параметр:  Максимальная глубина вложенности XML-сущностей
Значение:  задать пороговое значение под нагрузку приложения
Действие:  Block
Критичность: Высокая
```

Верифицировано: SCN-19 `253ddc3b-b3d1-4aa6-a197-55973030a3e8`.

### WAF-17: Блокировка зарубежного трафика (геофильтрация)

Встроенное правило PTAF Pro по геофильтрации. Работает по GeoIP. Для кредитных организаций, обслуживающих исключительно российских клиентов, рекомендуется использовать WAF-18 вместо WAF-17.

```
if NOT CLIENT_COUNTRY == "RU"
   AND NOT CLIENT_IP in [@@ip_list]
then Block
```

`@@ip_list` — список доверенных IP-адресов (партнеры, платежные системы, межбанковские шлюзы), которые не должны блокироваться по географическому признаку. Заполняется вручную в настройках PTAF Pro.

Действие: Block. Критичность: Средняя.

Верифицировано: SCN-20 `fa32548f-eda2-4858-9c1d-dd11753b6f7e`.

### WAF-18: Whitelist на RU

Альтернатива WAF-17 по принципу «разрешить только нужное»: пропускать только трафик из RU, остальной блокировать. Подходит для приложений, ориентированных исключительно на российских клиентов, что для розничного ДБО типично.

**Настройка через интерфейс PTAF Pro:**
```
Раздел:                  Геофильтрация
Режим:                   Whitelist
Разрешенные страны:      RU
Действие для остальных:  Block
Критичность:             Средняя
```

Верифицировано: SCN-21 `088dc764-36e6-4667-8788-11d13e1bc5fc`.

## Авторские правила

Авторские правила закрывают пробелы, которых в Default Template PTAF Pro нет совсем. Каждое подтверждено UUID события безопасности на стенде TRY PTAF.

### WAF-05: SQL injection в JSON-теле POST-запроса *(авторское)*

Слепое пятно базовой конфигурации: модуль `sqli_detector.so` не анализирует тело запросов с `Content-Type: application/json`. То же ограничение зафиксировано для ModSecurity в исследовании Qu et al. [1], где подтверждено, что отсутствие парсинга JSON-тела — архитектурное решение. Экспериментально пробел подтвержден сценарием SCN-10: тот же запрос на конфигурации A (без правила) события не вызвал, на конфигурации B был заблокирован.

```
if REQUEST_BODY matches ~"(OR 1=1|UNION SELECT|extractvalue)"
   AND REQUEST_CONTENT_TYPE == "application/json"
then Block
```

Действие: Block. Критичность: Высокая.
Привязка: CWE-89, CVE-2022-21587 (CVSS v3.1 9.8).

Верификация пробела: SCN-10 на конфигурации A — событие безопасности не сформировано (UUID отсутствует, поскольку WAF событие не зафиксировал).
Верификация правила: SCN-24 на конфигурации B, UUID `3fd5bb19-ab93-4710-afe4-a0e750565140`.

### WAF-14: Отрицательная сумма транзакции *(авторское)*

Вектор атаки на бизнес-логику банковского API. При передаче `amount=-100` наивная реализация спишет минус сто рублей с целевого счета — то есть фактически зачислит сумму в обратную сторону. Правило ловит запросы, где значение поля `amount` является отрицательным числом.

```
if REQUEST_PATH == "/vulnbank/online/api.php"
   AND REQUEST_POST.select("amount").extract(values).any()
      matches ~"^\-\d+$"
then Block
```

Действие: Block. Критичность: Высокая.
Привязка: OWASP API4:2023 (Unrestricted Resource Consumption / Business Logic).

> **Адаптация.** Маршрут и имя поля заменить на фактические для целевого приложения (например, `transferAmount` в `/api/v1/transfer`). Регулярное выражение на отрицательное число переносится без изменений.

Верифицировано: SCN-17а `ca3d20e9-5ae4-4645-9e93-23d2541281f3`, SCN-17б `628d436d-b7f2-41ed-be68-283b2d0ca417`, SCN-18 (блокировка) `847a91c0-e43a-4220-bbbf-0b8269f362e8`.

### WAF-15: CRLF Injection (CWE-113) *(авторское)*

Тихий вектор компрометации сессий. Если приложение отражает значение GET-параметра в HTTP-заголовок ответа (например, в `Location` при редиректе) без экранирования переводов строк, атакующий через `%0d%0a` в параметре внедряет дополнительный заголовок `Set-Cookie` и перехватывает сессию клиента банка. Тестовый запрос на стенде: `?redirect=%0d%0aSet-Cookie:session=hacked`.

```
if REQUEST_QUERY matches ~"%0[aAdD]|%0[aA]%0[dD]"
then Block, Log
```

Действие: Block + Log. Критичность: Высокая.
Привязка: CWE-113, OWASP A03:2021.

На конфигурации A событие безопасности не сформировано (пробел подтвержден), на конфигурации B заблокировано.

Верифицировано: SCN-25 `2f90213b-ac83-4f1e-b7ae-5d370f08ae47`.

### WAF-19: Sensitive Token in URL (CWE-598) *(авторское)*

Ловит передачу секретов в строке запроса GET. Распространенная ошибка интеграции: API-ключи и OAuth-токены в URL попадают в access-логи nginx, балансировщиков и прокси, откуда легко утекают вместе с архивами логов и при отладке.

```
if REQUEST_QUERY matches ~"(token|api_key|apikey|secret|password|passwd|auth)="
then Block, Log
```

Действие: Block + Log. Критичность: Высокая.
Привязка: CWE-598, OWASP API2:2023.

> **Адаптация.** Список ключевых имен можно расширять под профиль конкретной организации: `access_token`, `bearer`, `session_id`, `jwt` и т.д.

Верифицировано: SCN-26 `ca588b4d-f13f-44c1-8400-ccd655e385db` (`token=eyJhbGc...`), SCN-27 `22322a5e-f267-460d-af43-e923017a251d` (`api_key=sk-prod-bank-secret123`).

### WAF-20: OTP Bruteforce / Account Takeover *(авторское)*

Реализована не кодом правила, а настройкой через интерфейс PTAF Pro в разделе «Параметры аутентификации». Базовое правило brute-force ориентировано на пароли, и перебор четырехзначного OTP-кода ему недостаточно похож на типовой пароль, чтобы сработать. Решение — отдельная настройка с агрегацией по попыткам ввода SMS-кода.

**Настройка через интерфейс PTAF Pro:**
```
Раздел:          Параметры аутентификации
Тип:             На основе форм
Метод:           POST
URL:             /vulnbank/online/api.php
Поле логина:     username
Поле OTP:        sms_code
Коды успеха:     200
Коды неуспеха:   400, 502
Cookie:          PHPSESSID

Агрегация:
  Порог:         10 срабатываний за 30 секунд с одного IP
  TTL:           10 минут
  Действие:      Aggregation blacklist
```

Действие: Block + blacklist. Критичность: Высокая.
Привязка: OWASP API4:2023.

> **Адаптация.** URL эндпоинта, имена полей и коды ответов заменить на фактические для целевого приложения.

На стенде ловится серия из 12 последовательных событий перебора SMS-кода с одного IP, после чего агрегация переводит адрес в blacklist.

Верифицировано: SCN-29 `3d5c1ad6-049a-4a72-8b4b-a73ce0bc34ea`.

### WAF-21: Credential Stuffing Detection *(авторское)*

Ловит характерный признак словарной атаки: очень короткие имена пользователей (1-3 символа). При credential stuffing атакующий прогоняет словарь, в котором первые сотни записей — короткие ники с типовыми паролями. Длинных нормальных имен пользователей в таких словарях обычно нет.

```
if REQUEST_PATH == "/vulnbank/online/login.php"
   AND REQUEST_METHOD == "POST"
   AND REQUEST_POST.select("username").extract(values).any()
      matches ~"^[a-zA-Z0-9]{1,3}$"
then Block, Log
```

Действие: Block + Log. Критичность: Высокая.
Привязка: OWASP API4:2023.

> **Адаптация.** Если в реальном приложении есть легитимные пользователи с короткими `username`, правило надо смягчить (например, снизить порог до 2 символов или дополнить условием «более 5 разных username с одного IP за минуту»). Маршрут заменить на фактический.

Верифицировано: SCN-30 `8b7c40f6-d4f7-4307-8dcb-8820012c2d19` (тестовый `username`: `aa`).

### WAF-22: Mass Assignment *(авторское)*

Защита от подмены служебных полей в JSON-теле запроса. Классическая уязвимость API: клиент отправляет `{"name": "John", "is_admin": true}`, сервер делает `User.update(params)` без явного allowlist полей — и пользователь становится администратором.

```
if REQUEST_BODY matches ~"(\"admin\"|\"role\"|\"is_admin\"|\"is_superuser\"|\"permissions\")"
then Block, Log
```

Действие: Block + Log. Критичность: Высокая.
Привязка: OWASP API6:2023 (Mass Assignment).

> **Адаптация.** Список полей в регулярке следует расширять под кодовую базу конкретного приложения: `is_staff`, `superuser`, `account_type`, `manager_level` и т.д.

Верифицировано: SCN-28 `52e6abf3-172c-4f58-8296-4f0e8ab4794c` (payload: `admin:true`, `role:superuser`).

### WAF-23: Server-Side Template Injection, SSTI (CWE-94) *(авторское)*

SSTI — это RCE через шаблонизатор приложения. Если приложение рендерит шаблон Jinja2/Twig/FreeMarker с пользовательским вводом без экранирования, выражение вида `{{config.__class__.__init__.__globals__}}` выполняется на сервере и дает полный доступ. Правило ловит характерные синтаксические конструкции в теле или query-параметрах.

```
if REQUEST_BODY matches ~"[{][{][^}]+[}][}]"
   OR REQUEST_QUERY matches ~"[{][{]|[$][{]|[#][{]"
then Block, Log
```

Действие: Block + Log. Критичность: Высокая.
Привязка: CWE-94, OWASP A03:2021.

Регулярка покрывает `{{...}}` (Jinja2, Twig), `${...}` (Velocity, FreeMarker, Spring EL), `#{...}` (Thymeleaf, JSF).

> **Адаптация.** В продакшне стоит проверить, не используются ли подобные конструкции в легитимном API (например, в полях с шаблонами писем или в markdown-разметке).

Верифицировано: SCN-31 `a2e4cd59-7ac2-46f5-9b0e-6430211a3267` (payload: `{{config.__class__.__init__.__globals__}}`).

### WAF-24: XML Signature Wrapping, XSW (CWE-347) *(авторское)*

Атака против SOAP-протоколов с цифровой подписью. Атакующий копирует элемент `<Signature>` от валидного запроса и оборачивает его вокруг поддельного XML-тела. Парсер верифицирует подпись как валидную, но интерпретатор бизнес-логики читает подмененное содержимое. Техника применялась в атаке на Bangladesh Bank (2016, ущерб 81 млн долларов через систему SWIFT).

```
if REQUEST_BODY matches ~"<[a-zA-Z:]*Signature[^>]*>.*<[a-zA-Z:]*Signature[^>]*>"
then Block, Log
```

Действие: Block + Log. Критичность: Высокая.
Привязка: CWE-347, OWASP API8:2023.

Регулярка ловит повторение тега `Signature` в одном запросе. Префикс `[a-zA-Z:]*` нужен для namespace-префиксов: `<ds:Signature>` (XMLDSig), `<wsse:Signature>` (WS-Security).

Верифицировано: SCN-32 `8f667617-ab8d-406e-a489-7f39482b6eef`.

## Что не удалось верифицировать на стенде

Из 24 разработанных правил 20 подтверждены UUID событий безопасности на стенде TRY PTAF (включая WAF-12, реализуемое встроенным модулем). Следующие правила потребовали условий, которых в лабораторной среде не нашлось:

- **WAF-13** (обращение к загруженному webshell): правило написано, но воспроизвести сценарий «загрузка webshell -> обращение к `/uploads/*.php`» на лабораторном Vulnbank не получилось из-за конфигурации файловой системы.
- **HTTP Method Override** (`X-HTTP-Method-Override: DELETE`): nginx в конфигурации стенда не пробрасывает нестандартные заголовки до приложения — событие не формируется.
- **HTTP Request Smuggling**: nginx 1.24.0 нормализует конфликт `Transfer-Encoding` / `Content-Length` до передачи агенту. Требует специально собранного стенда с уязвимым балансировщиком.
- **Path Traversal через URI**: nginx нормализует путь до агента, запрос вида `/../../../etc/passwd` уходит в HTTP 400 еще до проверки правилом. Логика правила переписана под вектор через GET-параметр и подлежит верификации в продакшне.

Перечисленные правила проходят валидацию при пилотном развертывании в production-инфраструктуре или на стенде с расширенной конфигурацией балансировщика.
